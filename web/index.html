Keyless funds on NEAR

A fund nobody can change.
An exit nobody can block.

Plinth funds have no keys. The rules are fixed at launch, the manager can only propose swaps that the contract checks against a signed NEAR Intents quote, and every depositor can take their share of every token out, at any time, in kind.

    Limits

    Read these before you trust it

    An independent adversarial review found one critical and three high-severity issues on 2026-11-10. All are fixed or bounded below, each with a regression test.

    • No fixes, ever. A keyless contract cannot be upgraded. A bug is permanent, so funds should start small.
    • 1Click is trusted to deliver. The contract checks the signed quote; it cannot force delivery. If 1Click refunds, the refund goes back to the fund.
    • Prices are 1Click's. The cost cap uses the USD marks in the signed quote, so it bounds cost against the venue's own valuation, not against the whole market.
    • One signing key. 1Click's key is fixed in the fund. If it rotates, the fund can no longer trade, but redemption still works.
    • Testnet stand-in. 1Click has no testnet, so the recorded run uses a test signer and a solver account in 1Click's place. The verifier labels it.
    • App fees are bounded, not blocked. 1Click does not sign its app-fee field, so an operator can take a fee inside a trade. The cost cap still bounds it: at most the cost cap of each trade, each trade capped, a fixed number of trades per day.
    • At most 4 tokens. So one redemption can pay every token in a single transaction.
    • Exit waits for one trade. While a trade is in flight, redemptions wait up to 10 minutes. After that you can leave without your share of that one trade.
